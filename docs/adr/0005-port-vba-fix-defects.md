# Повторяем алгоритмы VBA надстройки, явные дефекты исправляем

Эталон поведения — алгоритмы из исходников VBA !SEMTools, а не «как правильно» с нуля и не прогон надстройки в Excel. Отступаем от VBA только там, где у неё дефект или побочный эффект Excel (решения Человека 2026-10-16): ё = е при сравнении; стоп-слова без учёта регистра; пустые ячейки никогда не дубли; фраза делится по любым пробелам, двойных пробелов в результатах нет; леммы в нижнем регистре; n-граммы сортируются по убыванию счёта; маркеры — в написании списка, через «, ». Регулярные выражения понимают кириллицу: классы \w, \b, \d в режиме Unicode, а не ASCII, как в VBScript (решение Человека 2026-10-17). Украинский текст (chars('ua')) — по буквам і ї є ґ, а не по 31 элементу `fua`: окончания вроде «ати » ловят русские слова («кровати»). Удаление топонимов с предлогами убирает топоним целиком: VBA (`udalit_toponimy_s_pryedlogami`, стр. 1194–1197) при одном топониме на первое слово отрезает только предлог и следующее слово («отели в хересе де ла фронтере» → «отели де ла фронтере»). Удаление по списку фраз и маркеров сохраняет регистр: VBA (`DeletePhrases`) переводит в нижний регистр всю ячейку, даже когда ничего не удалено. Список предлогов исправлен: в VBA (`prps`, стр. 1322) «пo» набрано с латинской «o», поэтому «по» никогда не находится, а мусорное слово «g» лишнее; то же «g» убрано из стоп-слов. Пустой элемент пользовательского списка — ошибка аргумента: в VBA пустая ячейка в выделенном списке совпадает с любой фразой (начинается, заканчивается, содержит) и делает «Все из списка» ложным для всех. Извлечение маркеров берёт самое длинное совпадение («как сделать», а не «как»): VBA (`la—`) берёт первый подходящий элемент в порядке списка, и короткий маркер закрывает длинный. Счётчики повторений и номер встречаемости не считают пустые ячейки: VBA (`––k—`, `–kko`) считает все пустые одной группой. Словоформы слова, которое не лемма, — формы его леммы без повтора исходного слова: VBA (`––aa`) пишет исходное слово дважды. Явное улучшение там, где Python может больше VBA (как регулярные выражения с кириллицей), и противоречия решаем без отдельного вопроса, в пользу более качественного варианта. Каждый отход записываем сюда: как было в VBA и почему сделали иначе (решение Человека 2026-10-17). Как в VBA: n-граммы считают вхождения; биграммы «w1+w2» без удаления стоп-слов по умолчанию.
