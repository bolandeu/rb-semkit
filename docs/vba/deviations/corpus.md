# Отходы от VBA: область corpus

Операции над всем семантическим ядром: комбинации, родители и базисы, разбиение на хорошие и плохие, кластеризация,
синонимы в минус-слова, опечатки, тональность (`src/rb_semkit/core/corpus/`, SEMKIT-013). Здесь — отходы от алгоритмов
надстройки по ADR 0005: правило (его цитируют случаи сверки `tests/conformance/cases/corpus/`), как было в VBA и почему
сделали иначе. Общие правила (ё = е, пробелы, стоп-слова без учёта регистра) — в ADR 0005.

## Родители, дети, базисы

- **Фраза никогда не родитель самой себе.** «Ближайших родителей» (`–—·o`, `FindParentInDicts`) перебирает сочетания слов
  ребёнка вместе с ним самим, поэтому фраза из списка родителей — родитель самой себе, и её перестановка тоже;
  «Первых родителей» и «Первые вложенные фразы» (`isChild`) сравнивают строки целиком, и перестановка слов — родитель или
  ребёнок. Почему: родитель — фраза шире ребёнка; фраза с теми же словами в другом порядке — неявный дубль, а не родитель.
  Поэтому у нас фраза никогда не родитель самой себе, ни в каком порядке слов.
- **Слова сравниваются без учёта регистра.** Родители, дети, кластеры по частотному словарю и словарь тональности в VBA
  сравнивают слова бинарно: «Стол» не «стол». Почему: регистр не меняет смысла фразы ядра; как и дубли (ADR 0005), слова
  сравниваются без учёта регистра и с ё = е.
- **Родитель длиннее шести слов тоже находится.** VBA не кладёт в словарь родителей длиннее 6 слов и перебирает сочетания
  слов ребёнка не длиннее 6. Почему: предел защищал от перебора; поиск по набору слов в Python находит родителя любой длины.
- **Пустые ячейки списка пропускаются.** В «Первых родителях» пустая ячейка списка — родитель любой фразы и даёт «»;
  «Комбинации по 2 элемента» составляют пары с пустой ячейкой; «Генератор линейных комбинаций» читает столбец только до
  первой пустой ячейки. Почему: пустая ячейка — не элемент списка; у нас её пропускают, а элементы под ней не теряются.
- **У пустой фразы нет родителя и ребёнка.** В «Первых вложенных фразах» пустая фраза получает первым ребёнком первый
  элемент списка. Почему: у пустой фразы нет слов, и детей у неё тоже нет; результат — «».

## Комбинации

- **Пары — из разных элементов списка.** «Комбинации по 2 элемента» (`oa·k`) составляют пары из разных строк, поэтому две
  одинаковые строки дают пару «a\a» — элемент с самим собой. Почему: пара элемента с самим собой бесполезна; каждый элемент
  берётся один раз, в порядке первой строки.
- **Таблица результата — по колонке на каждое значение.** «Комбинации по 2 элемента» пишут пару одной строкой «a\b» и
  рядом бесполезный столбец FALSE; «По топ-10 выдачи» пишет кластер одной строкой через «, »; синонимы — два листа.
  Почему: результат-таблица библиотеки — DataFrame: пары — first, second; кластеры по выдаче — phrase, cluster (номер, 1 —
  самый большой); синонимы — word, sure (из подобранной фразы или из поискового запроса, на проверку), synonyms.
- Предел размера результата — аргумент `limit` (по умолчанию 1 048 576, строки листа Excel), а не жёсткое сообщение
  «Тут слишком много комбинаций!»; превышение — InvalidArguments с названием предела. Случаев сверки нет: VBA результата не
  даёт.

## Кластеризация

- **Кластер по частотному словарю — набор слов, а не их порядок.** «По частотному словарю» (`O–—–`) оставляет частые слова
  в порядке фразы, поэтому «купить диван» и «диван купить» — два кластера. Почему: кластер — набор слов; у нас слова
  кластера в нижнем регистре, самые частые первыми, затем по алфавиту, и одинаковый набор — один кластер.
- **Кластеризация по выдаче не переносится: её делает `sk.cluster_serp`.** «По топ-10 выдачи» (`SERPClustering`,
  `calculateScore`, `simScore`) считает для двух фраз позиционный счёт: каждый общий URL даёт 1, а в первых пяти позициях
  обеих — ещё бонус от худшей из двух позиций (бонусы 5 4 3 2 1 дают 15 10 6 3 1); фразы со счётом от 24 связаны, кластер —
  компонента связности (цепочка связей); кластеры идут по возрастанию размера, а фраза в двух строках листа — ошибка 457.
  Почему: компонента связности сцепляет A и C через B без единого общего URL, и кластеры цепляются друг за друга (ADR
  0007). Таблицу выдачи (phrase, position, url) кластеризует `sk.cluster_serp` мягким или жёстким методом по числу общих
  URL; случаев сверки для метода надстройки нет.

## Синонимы и минус-слова

- **Синоним считается от слова условия показа.** Скомпилированный `ook` из-за `Select Case InStr / Case True` всегда
  переворачивает пару, и исходным словом становится слово, которое позже по алфавиту («купить диван» / «купить софа» →
  «софа: диван»). Почему: задумано исходным брать слово условия показа; так и делаем.
- **Операторы соответствия убираются все.** VBA убирает из условия и подобранной фразы только «+», и «!диваны» не
  лемматизируется. Почему: операторы Директа (+ ! " [ ]) — не часть слова; у нас убираются все.
- **Минус-слово не добавляется, если синоним уже есть во фразе.** Скомпилированный `oo—–` дописывает каждый синоним,
  проверка «уже есть во фразе» никогда не срабатывает: «купить диван -софа» → «купить диван -софа -софа -тахта». Почему:
  задумано пропускать синоним, который уже стоит во фразе словом или минус-словом; сравниваем по леммам.

## Разбиение ядра

- **По леммам — всегда, без порога в три словоформы.** Книга `SEMToolsWordProcessor.xlsb` строит карту лемм, только когда
  в ядре не меньше трёх слов с другой леммой; иначе сравнивает слова как есть. Почему: порог случайный; у нас `lemmas=True`
  сравнивает леммы всегда, `lemmas=False` — слова.

## Опечатки

- **Опечатки ищутся без сети, по частотному словарю самого ядра.** «Является ли опечаткой?» и «Наиболее вероятное
  исправление» спрашивают подсказки Яндекса для каждой ячейки (таймауты 100 мс); без сети макрос останавливается, с сетью
  ответ зависит от сервиса. Почему: так решено в плане (§1.6, §3a): опечатка — редкое слово рядом (по Левенштейну) с
  частым словом того же ядра; это быстро и работает офлайн на 1M фраз. Проверка орфографии сервером LanguageTool —
  отдельный провайдер `sk.LanguageTool`.
- **Известная словоформа — не опечатка.** Частотный словарь ядра сам по себе считал опечаткой любое редкое слово рядом с
  частым: «москва» при частом «москве», «угловые» при частом «угловой», «дешево», «недорогой», «с диваном» — 263 верные
  фразы из 2000 ядра «купить диван» (сквозная проверка, docs/plans/e2e-quality.md, п. 17). VBA спрашивает подсказки
  Яндекса и этой ошибки не знает. Почему: опечатка — слово, которого нет в языке; у нас слово, которое лемматизатор по
  умолчанию знает (словарь !SEMTools или pymorphy3: «москве», «пружинном», «токио»), и стоп-слово опечаткой не бывают;
  исправление по-прежнему — частое слово ядра («купить диавн в мосвке» → «купить диван в москве»). Исправление
  начинается с той же буквы, что и слово: опечатка редко задевает первую букву, а сокращение не становится другим
  («с нпб» не «с спб»). На 2000 фразах ядра «купить диван» не отмечена и не изменена ни одна.
- **Расстояние Левенштейна считается по целым символам.** UDF `Levenstein` сравнивает только младший байт каждой единицы
  UTF-16, поэтому «а» (U+0430) равна «0» (U+0030). Почему: это дефект; сравниваем символы целиком.

## Тональность

- **Тональность фразы без маркера пустая.** В VBA среднее фразы без маркера делит 0 на 0, и макрос останавливается;
  минимум без маркера — 11111. Почему: у фразы без маркера оценки нет; у нас — пустое значение.
- **Максимум тональности может быть отрицательным.** Максимум в VBA начинается с 0, поэтому отрицательным не бывает.
  Почему: это дефект; максимум считается по найденным оценкам.
