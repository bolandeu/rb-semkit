
 Usage: semkit read [IN] nearest [OPTIONS] [AGAINST]

 For each row of the table, the rows of another table nearest it by meaning, in a long report.

 top: the matches of each row, the nearest first: a whole number from 1.
 threshold: the similarity from 0 to 1 a match needs to stay; without it every match stays.

 The texts of both tables get the page vector. The report has a row for each match of each row: the
 text of the row (in a column named as the working one), match, rank (1 for the nearest),
 similarity (4 places), and url (of the match) when the against table has a url column. A row with
 no match left (an empty cell, or every match below the threshold) keeps one row with an empty
 match.

 against: a file with the texts to match, one per row; the file is read like `read` does.
 against_column: the column of the texts in --against; by default the column text, else its first
 text column that is no url column.
 model: the encoder, pulled once with `semkit models pull NAME`: e5-small, bge-m3, potion, or
 hf:<id> of a model of the Hugging Face hub.

 A text longer than the input of the model is cut into pieces the model takes whole; its vector is
 the mean of the vectors of its pieces. When the table of the texts has the columns title and h1,
 its vector is the weighted mean of the text (weight 1), the title (2) and the h1 (1.5).

 The step takes the working column as the texts to match; the report replaces the current table.

 Example: semkit read core.csv nearest --against page_texts.csv --top 2 write out.csv
