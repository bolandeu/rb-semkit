## Problem

v1 covers find/remove/extract, duplicates, n-grams and lemmas. The rest of the add-in's work on a semantic core — changing text (case, translit, replace, match types, UTM, hashes, word order), declension, phrase structure (permutations, parents, basis phrases, good/bad split), clustering, minus-words, typos, sentiment — is still done by hand in Excel, and the CLI waits for the whole library.

## Goal

import rb_semkit gives every function of the add-in's menus except Mystem: each follows the VBA algorithm, the broken ones work as intended, and the conformance report lists for each function where it follows the VBA, where it differs and why.

## Acceptance (Given–When–Then)

- Given a phrase column, When any change function runs (case, insert, move, replace, split, reverse, sort, quotes, translit, ЧПУ, layout, similar chars, match types, minus-words, UTM, hashes, word order), Then the result is the VBA result with the ADR 0005 deviations; e.g. ЧПУ of «Диван-кровать 2 м!» is divan-krovat-2-m, utm source of a URL is the decoded value only
- Given a noun, an adjective or a full name, When declined to any case and number, Then the form is the intended one, not the add-in's broken one: «диван» genitive is «дивана», the accusative of a full name is the accusative, verbs and adverbs are left as they are
- Given a semantic core, When permutations, pairs, linear combinations, parents, children, basis phrases or the good/bad split run, Then the tables match the VBA handlers of docs/vba/analysis.md with the ADR 0005 deviations
- Given a semantic core, When clustered by the frequency dictionary or by a SERP table (phrase, position, url), Then the clusters match the VBA algorithm with its settings (bonuses, threshold) as arguments, and no network is used
- Given a semantic core, When irrelevant words, synonyms to minus-words, typos (Levenshtein against the core's own frequency dictionary) or sentiment by a user dictionary run, Then the results follow docs/vba/analysis.md with the ADR 0005 deviations, and the input is never changed
- Given the optional spelling provider (LanguageTool on homeserver), When it is slow, down or returns 5xx, Then semkit retries with backoff, then raises a project error naming the provider; it never returns a partial result silently
- Given lemmatize(..., fallback='pymorphy'), When a word is missing from the bundled dictionary, Then it gets the pymorphy3 lemma; by default the word stays as it is, as in the add-in
- Given a wrong input to any new function (no column, unknown case or list, bad threshold, empty dictionary), When called, Then InvalidArguments names the argument and the allowed values, and nothing changes
- Given the conformance cases, When the report is built, Then every new public function has its case file (VBA value, semkit value, rule and why where they differ) and its section in the conformance report
- Given 1M phrases, When the new data-backed functions run (declension, translit, clustering by frequency), Then each fits the benchmark budget
- Given the reference tables the new functions use (declension, translit, ЧПУ, layout, similar chars, phonetic, minus-word and sentiment lists), When the package is installed, Then they are bundled in fast Python formats, load once and lazily, and the data manifest checks each against its source
- Given any public docstring or help text, When read, Then it describes the behaviour in user terms, without the add-in's VBA handler names or line numbers (ADR 0006)

## Implementation decisions

- Python library rb_semkit run through uv; one CLI over the whole library by the cli-builder rules is the next epic.
- New public functions follow the v1 frame: a Series or a DataFrame column in, a new column <column>_<operation> or inplace out; functions whose result is a table return a DataFrame.
- Modules: change (text changes, match types, UTM, hashes, word order, phonetic), morph (declension of nouns, adjectives and full names, irrelevant words, the pymorphy3 fallback), analysis (combinations, hierarchy, basis, good/bad split, clustering, synonyms to minus-words, typos, sentiment), text (ready patterns, phrase-end prepositions, prepositional complements).
- Reference data: the add-in's tables are built into the package in fast formats (tries, compressed lists, compact JSON) by per-area build parts, with a per-area data manifest.
- Algorithms come from docs/vba/change.md and docs/vba/analysis.md and are improved where Python does better or the VBA is broken; each deviation is recorded with how the VBA did it and why, in a per-area deviations document that ADR 0005 points to. Product text never mentions the VBA (ADR 0006).
- The spelling provider is an optional provider interface (batching, limits, retry, stdlib HTTP), as plan §3a.
- Conformance: the case format and report of E-001, split per area so that areas are worked in parallel.
