## Problem

A semantic core often needs table work in the middle of a pipeline: frequencies from another export joined by phrase, a cluster as one row, a cell of synonyms as rows, a group written only in its first row, a sample to check, a wide table of regions. Today the Human leaves the pipeline for a file and Excel or another tool, and loses the chain.

## Goal

One semkit pipeline does these table operations in memory, as steps: group-rows, split-rows, lookup, fill-down, sample-rows, shuffle-rows, unpivot. Each is an atomic step with its help and examples, and each is a public function of the library.

## Acceptance (Given–When–Then)

- Given a table with a group column, When group-rows --by GROUP runs, Then there is one row per group with the group, its phrases of the working column joined by ', ' (--sep changes it) and count; columns named by --sum hold the sums of their numbers; other columns are dropped
- Given a cell 'диван, софа ,' in the working column, When split-rows runs, Then it gives two rows 'диван' and 'софа' with the other columns copied; --sep changes the separator; an empty part makes no row
- Given a lookup table file, When lookup FILE --on KEY runs, Then each row gets the lookup table's other columns (--take narrows them) from the first row whose key matches; a row with no match keeps empty cells, or is dropped with --matched-only; a column name the table has gets the suffix _lookup; the report says how many keys of the lookup table repeat
- Given phrases 'купить диван' in the table and 'Диван купить' in the lookup table, When lookup runs with --kind implicit, Then they match; with the default --kind exact they do not
- Given a column whose cells are empty or only spaces below a filled cell, When fill-down runs (by default on the working column, or on the columns named), Then each such cell takes the value above it; empty cells before the first value stay empty
- Given a table, When sample-rows --n N (or --share S) runs, Then N rows (or that share, rounded) stay in their order; with --seed the same rows each time; When shuffle-rows runs, Then the same rows come in a random order, the same with --seed
- Given a wide table, When unpivot --keep COL runs, Then the kept columns stay and every other column turns into rows of two columns, column and value (names changed by options), one row per kept row and unpivoted column
- Given a wrong input (a column the table does not have, --n with --share, a share outside 0..1, a negative --n, an empty separator, a lookup file that cannot be read or has no key column), When the step runs, Then semkit refuses before any row is written, and the message names what is wrong and the columns there are
- Given a pipeline with these steps, When it runs with --dry-run, Then every step runs and nothing is written; a failed step leaves the output file as it was

## Implementation decisions

- Each operation is a public function of the table area of the library (rb_semkit), on a DataFrame, and a Step of the steps table that wraps it; dir(rb_semkit) lists the new names
- lookup joins in semkit's own code, in memory (ADR 0012); it reads the lookup table like compare-lists reads its second list; the key is compared by the duplicate kinds (exact, explicit, implicit) of the dupes area
- group-rows and unpivot change the shape of the table: the working column after them is named in each step's help
- Step help follows the help standard: one-line summary, examples, every option with its default; help snapshots and the agent guide list the new steps

## Test seams

- The semkit command line pipeline: semkit read TABLE.jsonl STEP ... write -, on small JSONL tables (as the table bricks tests)

## Out of scope

- Several input files in one read, and writing a file per group: read/write changes, a later decision
- Excel features (formulas, formats, colours, sheets), network features (translation, LLM queries), dates and IDs
- Fuzzy lookup by letters (trigrams): nearest and the duplicate kinds cover it for now
- dataio: it stays the input/output tool; no change there
