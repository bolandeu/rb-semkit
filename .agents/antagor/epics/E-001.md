## Problem

Processing a semantic core (clean phrases, find duplicates, count n-grams, get lemmas, find markers) is done today by hand in Excel with the !SEMTools add-in: slow on big cores, not scriptable, not usable by agents or other tools.

## Goal

import rb_semkit gives Python functions over a pandas Series or table column: find/remove/extract by matchers (chars, words, regex, phrases, markers, stopwords, POS), duplicates of 4 kinds, n-grams and bigrams with counts, lemmas, POS and wordforms on the bundled !SEMTools dictionary. 1M phrases are processed in minutes. The comparison with the add-in on reference examples is a separate task after this epic.

## Acceptance (Given–When–Then)

- Given the bundled data, When lemmatize is called on «москве», «купила», Then it returns «москва», «купить»; POS returns n, v; all wordforms of «москва» include «москве»; a word missing from the dictionary gets a lemma by the suffix fallback, not an error.
- Given a Series of phrases, When find/remove/extract is called with a matcher (chars by type, spaces, chars by position, around a pattern, regex, whole words and word lists, words by content/case/position/POS, word repeats, stopwords, phrase list, cells by content/occurrence), Then find returns a bool mask, remove the cleaned text, extract the found part, all with the input index.
- Given marker lists (geo, mosmetro, questions, sale and the other 14) and a user list, When find/remove/extract is called with markers(...), Then all markers of several lists are found in one pass, case-insensitive, optionally with the preposition before a toponym.
- Given a column with duplicates, When dupes is called with kind exact | explicit | implicit | implicit by wordforms, optionally against another column, Then it marks all but the first, or including the first, or drops them, or keeps the first.
- Given a column and an optional weight column, When ngrams (n = 1..N, words or lemmas, with or without stopwords), bigrams ignoring word order, and word/char counts are called, Then they return a frequency table with count and weight sum.
- Given a DataFrame and column=, When any function runs, Then the result is a new column <column>_<operation> to the right and the source column is unchanged; with inplace it replaces the column.
- Given NaN or None cells, When any function runs, Then they are treated as empty strings, never as an error or the text nan.
- Given a wrong input (a missing column name, a non-text column, an unknown marker list, a bad regex, n < 1), When the function is called, Then it raises the project's InvalidArguments error naming the argument and the allowed values; nothing is changed.
- Given the same function called from two threads at once on first use, When the bundled data loads lazily, Then both get correct results and the data loads once.
- Given scripts/build_data.py and the sandbox sources, When it runs twice, Then it produces the same data files; when a source is missing it stops with a message naming the file; the data tests check row counts and known lookups.
- Given 1M phrases on the Human's Mac, When the benchmark script runs dupes, ngrams and lemmatize, Then each finishes in at most 2 minutes (benchmark outside the gate).

## Implementation decisions

- Library only; no CLI commands in this epic. Public API is re-exported from the package root (import rb_semkit as sk); logic lives under core.
- Input: a str-like pandas Series, or a DataFrame plus column=. Output: Series with the same index, or the DataFrame with a new column <column>_<operation> (inplace flag replaces). NaN is filled with an empty string at entry.
- Matchers (ADR 0004): objects built once (chars, spaces, positions, around, regex, words, word_content, word_case, word_position, pos, repeats, stopwords, phrases, markers, cells) and three verbs find, remove, extract. A thin pipe(df, column) chains them.
- Tokenizing: split by whitespace; ignore_punct flag strips punctuation. Comparison uses the shared norm_phrase key (NFKC, lower, ё→е, collapsed spaces); output text keeps its original form.
- Morphology (ADR 0003): a Lemmatizer protocol (lemma, pos, forms); SemtoolsLemmatizer over marisa-trie (wordform → lemma+POS, lemma → wordforms) with the lemmSuf fallback and a per-run unique-word cache. Functions where lemmas are optional take lemmatizer=None (words as they are); lemma-only functions (lemmatize, pos, forms, dupes by wordforms) use the bundled one by default. POS codes nv, prt are returned as is.
- Reference data (ADR 0002): built by a re-runnable build script from the sandbox sources into package data, committed: lemmas and forms tries, lists (stopwords, prepositions, abbreviations), 18 marker lists compressed with an Aho-Corasick automaton built on first use. Declension tables are built but declension is v2.
- Performance: operate on unique phrases or words and map back; vectorized pandas string methods for regex.
- Errors: wrong arguments raise the template's InvalidArguments (a CliError, exit 2 later in the CLI).

## Test seams

- Public library API: import rb_semkit, call functions on small Series/DataFrames, compare outputs.
- Lemmatizer protocol: inject a tiny fake lemmatizer to test lemma-dependent logic apart from the data.
- Data build: run the build script, check the produced files (counts, known lookups, every marker list loads).

## Out of scope

- CLI commands (next epic, after the API settles); I/O through dataio comes with the CLI (ADR 0001).
- v2 functions: declension and the pymorphy3 extra, ready patterns, prepositional complements, translit, layout switch, match types, UTM, hashes, parents/children, basis, clustering, split by good/bad words, permutations.
- Spelling check (LanguageTool provider, local dictionary) and typos by Levenshtein: later.
- mystem; updating marker lists from semtools.guru; Excel-only features; LLM; SEO APIs.
