## Problem

After E-005 the Human can place phrases against a core, a query report and pages, but cannot match any two tables by meaning, cut texts into paragraphs, see which core phrases a text covers by meaning, make small ad groups of one intent or get synonym candidates; core gaps, competing pages, internal links, ad fit and competitor topics have no ready path.

## Goal

semkit has the atomic commands nearest, split-paragraphs, coverage-meaning, ad-groups and synonym-candidates; long texts are compared by a page vector. The scenarios built from them (core gaps, competing pages, internal links, ad fit, competitor topics) are recorded in the vectors plan for later.

## Acceptance (Given–When–Then)

- Given a core and --against a table of texts, When nearest --top 3 runs, Then every phrase gets three rows (match, rank 1-3, similarity) in a report; --top 0 or a missing --against file is refused with exit 2 naming the flag
- Given a pages table with a long text and title and h1 columns, When nearest or assign-pages runs, Then the page is compared by its page vector (pieces averaged, title and h1 weigh more); without title and h1 the text alone is used
- Given a text file, or a table of url and text, When split-paragraphs runs, Then the report has one row per paragraph (url, number, paragraph); blocks between empty lines are paragraphs and a heading line is a paragraph of its own; an empty text gives no rows
- Given a core and a text, When coverage-meaning runs, Then every phrase gets its best paragraph, the similarity and covered yes/no by threshold; with a cluster column, a cluster is covered when any of its phrases is
- Given a core, When ad-groups runs, Then phrases that are duplicates by meaning of each other share a group, a refinement makes another group, --max-size splits a larger group by vector, and the group name is its most frequent phrase; --max-size 0 is refused with exit 2
- Given a core and RuWordNet and navec pulled, When synonym-candidates runs, Then each core word gets candidates with the source and a score; without the data in the cache the step fails with the ready models pull command; the 100 labelled word pairs are its quality test, skipped with a message without the data
- Given the default thresholds of the new steps, When they are tuned on the e2e fixtures, Then the Architect shows a sample to the Human before release and the Human accepts them

## Implementation decisions

- Step nearest: the working table against --against, top --top matches with rank and similarity, in a report; it uses the base of E-005 (registry, encoder, index, --model, --threshold, the test encoder)
- Page vector: the text cut into pieces the model takes whole, piece vectors averaged with more weight for title and h1 when present; shared by nearest and assign-pages
- Paragraph unit: a block between empty lines, a heading line is a paragraph; step split-paragraphs gives it as a report
- Step coverage-meaning beside the word coverage; step ad-groups on the equivalence of dupes --kind meaning; step synonym-candidates with RuWordNet and navec pulled as models (ADR 0009)

## Test seams

- The semkit CLI pipeline (semkit read IN STEP ... write OUT) with the deterministic test encoder of E-005
- The encoder and word-vector interfaces with real cached data, for the quality test of synonym-candidates only

## Out of scope

- The scenarios (core gaps, H1 and title candidates, competing pages, internal links, ad fit, competitor topics, off-topic paragraphs): recorded in the vectors plan, built later
- Fetching page texts or SERPs
- Generation by an LLM; GPU
- Renaming the word list stop/semtools
