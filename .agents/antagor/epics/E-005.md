## Problem

The Human finds duplicates by meaning, clusters without a SERP, off-topic phrases, the target queries of a search query report and the page for each phrase by hand: semkit compares phrases only by their words and forms, so «диван недорого москва» and «недорогой диван» or «угловой диван» and «диван угловой купить» are not seen as one intent, and a core of thousands of phrases takes hours.

## Goal

With the vectors extra installed and a model pulled once (semkit models pull), the Human runs dupes --kind meaning, cluster-meaning, off-topic, classify-queries and assign-pages in a pipeline and gets candidate columns with a similarity; nothing is dropped by these steps; a checked-in quality test on 200 labelled phrase pairs shows the default model and threshold separate same and different intents.

## Acceptance (Given–When–Then)

- Given the vectors extra and no model in the cache, When semkit models pull e5-small runs, Then the model is in the system cache (or models.dir) at a fixed revision with its checksum checked, and semkit models list shows it as pulled with its size; a second pull of the same model says it is already there and downloads nothing
- Given a pull that fails (no network, an interrupted download, a wrong checksum), When it ends, Then no partial model is left in the cache, the exit is non-zero and the message names the cause and the command to retry
- Given two semkit models pull of the same model at once, When both end, Then the cache holds one valid copy and neither run leaves a broken one
- Given a model pulled by mistake, When semkit models remove NAME runs, Then it is gone from the cache and from models list; an unknown or not pulled name is refused with exit 2 and the list of pulled models
- Given an unknown --model name (not a short name and not hf:<id>), When any step by meaning runs, Then it is refused with exit 2 naming the allowed short names (e5-small, bge-m3, potion) and the hf:<id> form
- Given a step by meaning and its model not in the cache, When the pipeline runs, Then nothing is downloaded and the step fails with an error that gives the ready semkit models pull command
- Given semkit installed without the vectors extra, When a step by meaning or semkit models runs, Then it fails with an error naming the install command of the extra, and every other step works as before
- Given --threshold outside 0..1, When a step by meaning runs, Then it is refused with exit 2 naming the step and the flag
- Given a core, When dupes --kind meaning runs, Then a phrase is marked a duplicate only when its vector is close by the threshold and the words that differ are only non-refining words (bundled @meaning/neutral plus the Human list), synonyms, the word form, the word order or the --home city; a similarity column names the closest phrase kept; another refinement (type, size, material, room, brand, another city) is never a duplicate
- Given a core, When cluster-meaning runs with one --threshold, Then every phrase gets a cluster; a phrase without neighbours is a cluster of one; the cluster name is its most frequent phrase with --freq or else the phrase nearest its centre; two runs on the same input give the same clusters
- Given a core, When off-topic runs, Then every phrase gets a 0-1 score of distance from the centre of the core weighted by frequency (or from --seed phrases) and a flag by threshold; no row is dropped
- Given a search query report and --against a core, When classify-queries runs, Then every query gets the nearest core phrase, the similarity and target yes/no by threshold; no row is dropped
- Given a core and a --pages table (url, text), When assign-pages runs, Then every phrase gets the best page and its similarity, the second page and its similarity; a pages table without a url or a text column is refused with exit 2 naming the missing column
- Given a core above about 300k phrases, When a step by meaning runs, Then it uses the approximate index (HNSW) instead of the exact one, the step summary names which, and two runs give the same result
- Given the 200 labelled phrase pairs in the repository and the default model in the cache, When the gate runs, Then the quality test checks the cosine separates same and different intent (ROC AUC at least about 0.93) and the default threshold; without the model in the cache it is skipped with a message naming the pull command
- Given the default thresholds, When the cluster threshold is chosen on the sofa core, Then the clusters are shown to the Human, who accepts them before release

## Implementation decisions

- Optional extra rb-semkit[vectors]: the encoder, faiss-cpu and the model download; the base install does not change
- Model registry: short names (e5-small default, bge-m3, potion) map to a Hugging Face id, a fixed revision and a checksum; hf:<id> takes any model; the model store lives in the system cache (platformdirs) or models.dir of the config (ADR 0009)
- semkit models command group: pull, list, remove; a pull downloads into a temporary place and moves it in at once, under a lock per model
- Encoder interface: phrases in, normalized float32 vectors out, batched; the test suite registers a small deterministic test encoder under a test name; ONNX runtime instead of torch when its vectors match (cos above 0.999), decided by the worker on a measure
- Vector index: exact inner product up to about 300k phrases, HNSW above, with fixed seeds; all steps by meaning share it and the --model and --threshold options
- Steps in the step table: dupes gets the kind meaning; new steps cluster-meaning, off-topic, classify-queries, assign-pages; each adds columns and never drops rows (dupes --action drop keeps its existing meaning)
- Bundled word list @meaning/neutral of non-refining words; the Human list adds to it; --home names the home city
- Default thresholds come from the labelled pairs (e5-small best-F1 on phrases about 0.969); the cluster threshold is tuned on the sofa core
- Quality fixture: the 200 labelled phrase pairs (and the 100 word pairs, kept for the second epic) checked in under tests

## Test seams

- The semkit CLI: the pipeline (semkit read IN STEP ... write OUT) and semkit models pull/list/remove, with a deterministic test encoder registered in place of a real model
- The encoder interface with a real cached model, for the quality test on the labelled pairs only

## Out of scope

- The second vectors epic (IDEA-237): cannibalization, gaps, H1 candidates, internal links, copywriting, ads, word synonyms and text coverage by meaning
- Generation by an LLM
- Any download inside a pipeline step
- Dropping rows by a step by meaning (only candidates in columns)
- Fetching a SERP (another tool)
- GPU support
